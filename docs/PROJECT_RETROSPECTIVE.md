# 项目复盘：为什么停止 AgentPlatform

日期：2026-10-13。状态：`DISCONTINUED`。本复盘记录用户确认的停止原因，并把验收事实与分析判断分开。历史失败和通过记录均保留原结论。

## 最初要解决的问题

用户希望把产品开发目标交给一个平台：主 Agent 理解目标、提出方案并安排多个 Agent 完成具体工作；平台负责权限、执行、测试、审查、整合与记录；用户主要参与产品方向、权限等关键决定，并得到可继续迭代的软件产品。决定脉络见[项目决定摘要](PROJECT_DECISIONS.md)。

## 实际做出了什么

- **可信任务内核**：Git + Codex CLI 的一次受控任务走通了只读 Architect、受管 worktree、Worker、平台 TestRun、确定性 Gate 和只读 Final Gate；用户通过了当时的 UI 验收。指定功能路径 PASS，广泛运行可靠性 PARTIAL。[验证记录](VERIFICATION_RECORD.md)
- **本地产品流程**：目标与版本、用户确认的计划、绑定仓库、单 Task 关联、有限运行、静态预览、未发布交付及指标界面逐步落地。Phase 1.20–1.34 有离线、合成夹具、技术 UI 和开发包验收记录。[验证记录](VERIFICATION_RECORD.md)
- **可核对的工程材料**：JSON Schema、IPC 合同、SQLite 迁移、阶段计划、失败记录、原始证据哈希和独立测试。见[实现架构](ARCHIVE_ARCHITECTURE.md)与[数据/接口](ARCHIVE_DATA_INTERFACES.md)。

这些成果没有组成用户需要的完整产品体验。用户对新产品层真实业务效果未作通过验收，动态多 Agent 分工与集成未实现。

## 停止的决定

**首要原因是核心体验未实现。** 第一次以真实产品目标正式使用原 App 时，规划请求返回 `RUNTIME_NOT_QUALIFIED`，在任何 Agent 派发和开发 Task 创建之前停止。产品记录得以保存，但没有产出该产品。见[正式试点](PILOT_CASE_STUDY.md)。这次直接暴露出“已完成多个局部阶段”与“平台能接下一个产品目标”之间的差距。

**第二个原因是差异化不足。** 用户判断包括 Codex 在内的现有 Agent 产品已能满足自己的需求；即使继续补全编排，AgentPlatform 也可能只形成额外的 token 中转层，偏离最初要解决的问题。这是项目停止的产品判断，不是对所有竞品功能的等价性证明，也不是“多 Agent 平台不可行”的技术结论。[项目决定摘要](PROJECT_DECISIONS.md)

## 由证据支持的复盘

| 观察 | 依据 | 对项目推进的影响 |
| --- | --- | --- |
| 阶段技术验收覆盖组件和受控夹具，产品级真实闭环未运行 | [验证记录](VERIFICATION_RECORD.md) | “局部 PASS”容易被理解成核心体验接近完成；应分别报告两种进度 |
| 关键规划入口在正式 App 中保持未资格 | [正式试点](PILOT_CASE_STUDY.md) | 第一个真实需求在派发前被挡住，后续运行能力无法对用户产生价值 |
| 单 Task 串行角色链与用户想要的多 Agent 产品协作不同 | [架构导览](ARCHIVE_ARCHITECTURE.md)、[验证记录](VERIFICATION_RECORD.md) | 演示和验收不应把 Architect/Worker/Reviewer 顺序称作已实现动态协作 |
| 原始失败、超时、拒绝和未评估状态有留痕 | [验证记录](VERIFICATION_RECORD.md)、[去个人化试点](PILOT_CASE_STUDY.md) | 这些材料使停止决定可解释，也让工程方法可供借鉴 |

以下是**复盘推断**，不是独立实验结论：项目过早把阶段完成度当成主要进度代理；核心依赖长期未打通时仍扩大外围流程；真实产品试点来得太晚。更早地用一个真实目标贯穿“规划→派发→验证→交付”，并把它设为产品继续投入的前置门槛，可能更快暴露偏差。我们没有同条件竞品对照或充分样本，不能给出成本、速度或质量优于现有工具的结论。

## 值得保留的技术思想

工作区与权限分层、平台启动的测试、确定性硬门禁、版本化目标与幂等回执、输出契约和证据哈希，都有独立的学习价值。它们适用于需要审查与恢复的 Agent 执行场景，但在本项目中**没有证明**足以构成一个有差异化价值的独立产品。

## 归档原则

GitHub 呈现可维护源码、技术架构、数据与接口、真实状态和复盘，供读者理解与借鉴；不把本机数据库、会话原文、WSL 环境或所有运行工件原样上传。仓库中的证据索引只证明本机留存材料曾通过校验，不等于 GitHub 包含了全部证据。历史计划和路线图保留为历史材料，不作为未来承诺。精选仓库由用户决定公开，并以 MIT 许可证开放复用。
